# 显示定位与 DPI 验证

岛体使用 PerMonitorV2。位置取目标显示器的工作区与窗口当前 DPI，不使用主屏逻辑宽度来约束其他屏幕。宽度及横向模块共用运行时上限；屏幕变窄时立即收进工作区，避免从旧屏宽度慢慢缩回而暂时越界。用户保存的尺寸和显示器选择不会因运行时约束而改变。

DPI/显示器变化后重新计算布局并定位，显示器暂时缺失回到主屏，保留原选择供重新连接使用。位置计算支持负坐标，窗口暂时大于工作区时从工作区原点停靠，避免居中计算产生负向溢出。

## 已取得证据

- 核心几何断言：96/120/144/192 DPI、负原点、窄屏宽度、零 DPI 回退及超大窗口原点保护。算法断言不代表操作系统缩放验收。
- Windows 测试宿主也引用产品清单，并用原生 DPI 上下文 API 确认为 PerMonitorV2；旧宿主未显式引用清单，不能将其证据扩大成混合 DPI 验收。
- 当前实机只有 DISPLAY1，192 DPI（200%），工作区 3072×1920 像素。自建静音媒体驱动实际岛体，在 80/195/300 逻辑宽度、32/35/60 高度与两种形态下核对原生窗口矩形、居中、顶部偏移及物理像素尺寸，共 18 组通过。缺失目标显示器回退主屏且不改用户选择也通过。
- 严格定向证据：`artifacts/placement-strict/placement.json`；同场景早期证据在 placement-current。测试没有更改系统 DPI、分辨率或操作日用播放器。

尚缺实际 100/125/150% UI、混合双屏、负坐标实屏、主屏变更、拔插、全屏、物理输入及 Owner 对照体验。Owner 于 2026-11-04 将本次门槛改为本机当前环境；其他 DPI/混合屏未测不阻断本次交付，仍不能把单屏 200% 说成全环境通过。本机物理输入与试用问题继续闭环。

复测：`dotnet run --project tests/Capsule.WindowsTests -c Release -- --placement-test <独立证据目录>`。测试只移动自己的岛体窗口，不调整桌面设置。

## 独立视觉比例

个性化的“视觉比例”独立于 Windows DPI，默认 1 倍、最低 0.5 倍，以 0.05 加减并可还原；使用 VisualScale 保存，不与玻璃的背景放大倍率混用。整体缩放主岛体的字体、插件、圆角、通知、进度与按钮；设置窗口保持自己的尺寸。倍率和窗口收放采用相同缓动及帧率目标。

屏幕工作区不足时，运行时限制倍率，确保最小逻辑宽度和完整展开详情仍可到达；再按实际倍率约束逻辑宽度，保存的比例和尺寸不变。正常 1 倍在窄屏只约束宽度，不因设定宽度较大而额外压小字号。材质抓取和圆角合成使用实际物理尺寸，倍率改变使旧帧失效；命中区域随元素变换，通知上滑仍按内容逻辑距离计算。

当前单屏 200% 下的原生矩形验证已扩展为 0.5/1/1.5/2 倍 × 两种形态 × 三种宽度 × 三种折叠高度，共 72 组，证据 artifacts/placement-scale/placement.json。补充专项验证实际时钟、展开详情的超大偏好屏幕约束、唤醒按钮外侧原生命中、通知上滑阈值及设置加减/还原/重载；证据 artifacts/scale-tests/0b2fa802e2b74883910ac73b122238fa。亚克力在 2 倍下的帧尺寸及隐藏恢复也通过。

这些是自有窗口与消息验证，没有移动物理鼠标或调整系统缩放；完整混合显示器、驱动/刷新率、物理交互、长期资源及 Owner 体验门槛继续保留。
