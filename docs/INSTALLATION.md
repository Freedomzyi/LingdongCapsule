# 安装与维护

推荐从同版本 Release 下载 `LingdongCapsule-Setup-win-x64.exe`，双击进入欢迎页，选择位置后安装。进度对应准备、复制校验、更新和登记阶段，不显示虚假的倒计时。失败会保留原因并提供重试，成功后可打开应用。安装器包含完整程序及运行时，取消后清理自己的解压目录。

Windows“已安装的应用”中的卸载入口打开相同风格的卸载确认页。程序先按安装清单核对并复制维护界面至独立临时目录，再显示确认、进度和结果；退出后清理本次临时目录。取消不会卸载程序。个人设置始终保留，不提供容易误删的默认清空选项。安装、卸载沿用已有主题与字体；首次安装使用默认风格。

完整解压开发包后运行安装页，默认安装到当前用户 LocalAppData/Programs/LingdongCapsule，无需管理员权限。程序数据位于独立 LocalAppData/LingdongCapsule，安装脚本不读取或重置该数据目录。

当前发行方式不包含 Authenticode 数字签名，程序及安装、卸载脚本均未签名。下载后可按同一版本附带的 SHA256SUMS.txt 核对 ZIP；校验和用于核对文件完整性，不代表 Windows 发布者签名。正式版本的实际签名状态以对应 Release 说明为准。

升级先将原目录复制到同级临时目录，移除清单标记的旧程序文件，再复制并逐项校验新包。未纳入清单的自有文件保留；与新程序文件冲突时拒绝升级。全部完成后才停止目标目录的本程序并切换目录。复制失败清理临时目录，原安装不变。登记失败会尝试恢复原有卸载项、快捷方式、自启值及旧目录；若恢复登记本身失败会明确告警，仍继续文件恢复。

成功升级将旧目录保留在同级 `LingdongCapsule.previous-<唯一编号>`，不会自动删除历史备份。当前回退方式：退出本程序，保留新目录作为候选备份，把所选旧目录改回原安装目录名，再运行其中程序。路径保持不变可继续使用原快捷方式；跨版本登记和真实自启回退仍须完成维护验收。不要恢复个人设置目录覆盖升级后的用户选择。

卸载只删除清单中的程序文件、指向本安装的快捷方式/自启项和匹配安装位置的卸载项，保留自有文件和独立个人设置。目录联接/符号链接、越界或重复清单会在删除前拒绝。安装源和目标不能互相嵌套，非空且没有本程序清单的目标不允许覆盖。旧版备份不由新版本卸载连带删除。

`scripts/test-deployment.ps1` 使用独立证据目录、伪程序文件及 `-NoLaunch -NoRegistration`，核对文件安装、升级、复制失败、回退目录、卸载、用户文件冲突、越界和目录联接；不启动伪程序，不修改日用程序登记。构建会用 Windows PowerShell 5.1 执行该专项，发布脚本带 UTF-8 BOM。

`scripts/test-registration.ps1` 使用唯一测试身份，在当前用户真实注册表和开始菜单创建自己的临时登记，不修改日用软件的登记。覆盖安装、升级、迁移目录、自启参数保留、旧位置卸载保护和相似程序路径拒绝。测试在文件切换与快捷方式保存后注入登记写入异常，检查旧文件、注册表默认值及类型、快捷方式原字节和自启命令全部恢复；结束清理测试登记。构建同样以 Windows PowerShell 5.1 执行。

这些验证不等同本机真实权限拒绝、登录自启、应用启动/停止及设置迁移验收。本机实际维护仍须验证；2026-11-04 Owner 已取消干净系统/虚拟机作为本次门槛。安装后的交互启动不再要求隐藏窗口，但真实首次启动引导仍须单独验收。

## 配置保存与恢复

设置采用独立 settings.json，正常保存先写入唯一临时文件并刷盘，再原子替换，上一份有效设置保留为 settings.json.backup。启动只读配置，损坏时优先读取备份；两份都不可用时暂用默认值，并通过托盘及通用设置提示，读取阶段不覆盖原文件。

恢复后再次保存，会把损坏原件保留为 settings.json.rejected-<唯一编号>.json，不用坏文件替换有效备份。保存失败保留原配置并清理自己的临时文件。旧字段继续迁移，未知字段保留；更高 SchemaVersion 的设置只读使用，当前版本拒绝覆盖，磁盘在加载后变为更高版本也同样拒绝。

这些备份包含个人设置和本机路径，不应附到公开问题单。不要因程序回退而把旧设置强行覆盖到用户的新选择上。配置损坏与锁定写入已经隔离验证；磁盘故障、跨版本真实安装和掉电恢复仍需补充验证。

## 常驻后的再次启动

同一 Windows 登录会话内只保留一个主实例。手动再次运行或使用 --settings 启动，会向现有实例发送只含唤回语义的本机会话事件，打开设置；已最小化的设置恢复，关闭过的设置重新创建。--startup 重复启动保持静默。安装页 --install 仍可独立打开。

自建第二测试进程已验证实例互斥、跨进程信号、释放和重启；实际 WPF 设置窗口验证恢复及不重复创建。尚未证明 Windows 前台焦点策略、真实登录自启、不同路径便携版同时存在时的安装切换体验；它们仍需实际交互验收。

## 首次引导与自启保存

引导分为欢迎、外观、位置/模式、自启四页。使用现有设置字段，页面中暂存选择；开始使用时统一保存。稍后设置只记录引导完成，保留全部现有偏好；关闭未完成引导不写完成标记。已断开的显示器保留选择，运行时暂回主屏。

引导保存失败恢复内存选择及原自启登记，窗口保留错误反馈供重试。自启登记恢复保留原值类型和未展开命令，不用固定参数覆盖恢复值；不改变自启选择时不重写已有命令。设置页开关回调失败会恢复开关并显示错误，不通过未处理异常结束程序。

专项使用独立测试 Run 值和受锁定的自有设置文件，核对失败回退、实际四页 WPF、主题、返回/重试、跳过和未完成关闭；未改变日用启动项。这仍不替代实际 Windows 登录、首次安装及 Owner 引导体验验收。

## 引导与现有设置同步、短窗口导航

引导完成后，已经打开的设置页同步主题、材质、形态、显示器、待机和自启状态；设置窗口再次激活也会刷新这些状态。不重建页面、不重置滚动，也不为刷新额外保存配置。窗口高度不足时导航可滚动，末尾的关于入口仍可到达。

自启状态读取失败时，设置页显示反馈并禁用该开关，保留上次选择；再次读取成功后恢复。首次引导遇到同类故障时允许继续其他设置，自启保持未知且不可操作，完成引导不改启动项。读取故障专项通过注入回调完成，没有改变实际注册表权限。

## 构建输出与候选包

构建使用唯一暂存目录，确认自包含运行时关键文件、程序哈希、许可证清单与内容一致后，生成标准 ZIP 路径和校验和，再提交生成程序目录、ZIP 和 SHA256SUMS。提交中途失败会恢复上一组输出；清理只针对本次事务的备份，失败的发布暂存目录保留诊断。artifacts/app 是可再生的构建输出，正式安装和个人配置仍使用各自独立目录。

候选版使用 scripts/build.ps1 -RequireClean，开始和结束均核对提交及源码状态；未提交改动会拒绝候选构建，不替换现有包。普通开发构建仍可运行，BUILD-INFO.json 会如实记录 sourceDirty=true，不充当正式候选。插件按本次 SHA 清单选择、核对后复制，旧的额外 ZIP 不混入主包。

依赖许可不依赖 SDK 自动复制：构建从实际恢复包与 SDK 复制 .NET 许可，附带固定第三方来源和 Windows SDK 条款，生成 licenses/components.json 与文件哈希。缺失、不匹配及未审阅的新依赖会拒绝提交输出。关于页的 MIT 指本项目源码，各二进制依赖适用自己的条款。

解压验证脚本把子进程共享 DOTNET_ROOT 指向不存在的专用目录，并检查实际 coreclr.dll 来自解压包，确认 WPF 安装入口能初始化并正常关闭；不点击安装、不改日用设置。CI 另外在无本程序数据的 runner 中检查主岛体及首次引导。脚本拒绝在已有本程序数据的环境执行主程序首次启动测试。这类验证不能替代本机实际安装、自启登录和试用反馈。其他系统环境未测按实注明，不再阻断本次本机交付。
